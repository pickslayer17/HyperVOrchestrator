# TestRunner — VM provisioning project

> Точка входа в контекст. Прочитай целиком прежде чем что-либо делать или предлагать.

---

## 1. Что это

Автоматизация развёртывания Windows 11 ВМ на Hyper-V под автотесты FlaUI (.NET UI Automation). Параллельно **2-4 ВМ** на одном хосте. Цель — воспроизводимая установка и конфигурация тестовой машины с нуля.

Пользователь — сильный программист, sysadmin/DevOps впервые профессионально. Хочет **по-программистски структурно**, а не «куча скриптов в папке». Бытовой хаос сисадминства раздражает — это важно для тона.

## 3. Как оно устроено (реальность)

**Оркестратор** строит дерево суитов из папок `scripts/` (сорт по имени папки, `ScriptModelFactory`), гонит шаги по порядку, **останавливается на первом Failed**. Работает на любом PS (pwsh7 если есть, иначе 5.1) через раннер `powershell.exe -File`. Пути — относительно корня репо (от расположения exe). **Никаких абсолютных `D:\VMs`.**

**Суиты** — папки `scripts/NN-Area/`, порядок:
`00-CreateAndWinInstall` → `10-GuestSetup` → `20-HostNetwork` → `30-GuestNetwork` → `40-GuestDotnet` → `50-GuestOffice` → `60-Cleanup`.

**Шаг** = пара файлов в одной папке:
- `Verb-Noun.ps1` — «сделать дело».
- `Verb-Noun.check.ps1` — проверка ПЕРЕД шагом. Exit: **0** = надо делать (гнать main), **2** = уже сделано (скип), **1** = нельзя/ошибка.
- Чек снимает **реальную картину** (что у хоста, что у этой ВМ) и решает по ней — не по узкому «а оно вообще существует?».

**Скрипты — чистые функции**: не знают про корень репо и соседей, не дотсорсят; все значения приходят интерполяцией.

**Маркеры** (обрабатываются оркестратором до запуска):
- `@@key@@` — интерполяция из config+state (`@@vm.name@@`, `@@state.hostIp@@`). Сканируется **весь файл, включая комменты** — литеральный `@@key@@` без ключа БРОСАЕТ.
- `<<set::k=v>>` — записать в state (`<<set::state.vmIp=192.168.50.3>>`).
- `<<inject::path>>` — вставить содержимое файла.
- `<<ver::5=x,7=y>>` — версия-специфичный аргумент (5.1 vs 7).
- `$ScriptTarget = "Host"|"VM"` — где исполнять: на хосте / внутри ВМ через `Invoke-Command -VMName -Credential` (**PSDirect, не SSH**).
- `$RootPriviledges = $true` — тело в SYSTEM-таске (защищённые reg/службы/`netsh winhttp`).

**Конфиг**: `default.config.json` (в git, структура + пустые креды/пути) + `local.config.json` (gitignored, реальные), мерджится поверх. Что МОЖЕТ меняться в рантайме (IP, занятые порты) — не из конфига, а discover/verify/record в `Artifacts/state.json` через чеки. Конфиг = только константы (NATSwitch, dnsServer, prefix).

**Артефакты** (`Artifacts/`, gitignored): ISO, vhdx, office, unattend, `state.json`.

## 4. Что НЕ делать (важно)

- **Не делать async**. Шаги последовательно, синхронно. Параллелизм — точечно, когда задача потребует.
- **Не тащить SQLite / БД** для state. Только `Artifacts/state.json` или полагаться на чек каждый раз.
- **Не писать тесты** (xUnit и т.п.). Тулинг для одного человека — тесты сейчас overengineering.
- **Python-агент остаётся на Python.** На C# не переписываем.
- **Не делать SSH** для удалённого выполнения. Только WinRM/PSDirect + креды.
- **Не делать `--host <remote>`** сейчас, но раннер держать так, чтобы это добавлялось одной точкой.
- **Не вводить DI-контейнер** ради DI. Простой `new()` достаточно.
- **Не вводить структурный логгер** (Serilog и пр.). `Console.WriteLine`/файл достаточно.
- **Не предлагать Packer / Ansible / Terraform.** Решено: PowerShell + C# + Python. Альтернативы не обсуждаем.
- **Не использовать абсолютные пути** в коде/конфиге/скриптах. Корень — от расположения exe.

## 5. Стиль общения

- **Конкретика, а не вода.** Предлагаешь — предлагай **минимально необходимое**, не разворачивай 7 разделов из учебника.
- **Не overthink.** Задача «сделай X» — не эссе про индустрию.
- **Не повторять решённое** (раздел 4 в т.ч.). Не возвращаться без явной просьбы.
- **Опираться на реальный код**, не на абстракции. Рефакторинг — со ссылками на файлы и строки.
- **Русский — основной** в общении. Код/имена/комменты — английский. Комментов в коде почти нет.
- **Не льстить, не извиняться без нужды.** Облажался — признай в одну строку и дальше.
